# `3d models browse` — the interactive model browser

A full-screen terminal browser over the search, ranking and library actions of `3d models` (umbrella #570, slice
S7 #578). Results stream into a list while the sites answer, relevance verdicts update live while the classifier and
the planner run in the background, and one key per job previews, opens, downloads, slices or hands the picks to an
agent. Every key has a flag twin in `3d models act` that runs the **same** `library.actions` functions and returns the
same `3d.action/1` results (below), so what is learned in the browser works in a script.

```bash
3d models search "soil moisture sensor probe case" --tui   # a new ranked search, streamed into the browser
3d models browse                                           # resume the latest saved search tree (from the library DB)
3d models browse 01a16f7f-ca3b-7133-82ef-ce7c03312cfa       # or any saved search (id, uid, `latest`)
3d models browse latest --plain                            # the numbered prompt instead of the full screen
```

## Requirements and fallbacks

| Situation | What happens |
|---|---|
| terminal on stdin and stdout, `textual` installed | the full-screen browser |
| `textual` missing (extra `tui`) | exit **127** with `uv sync --extra tui`; nothing was searched |
| stdout or stdin is not a terminal, or `THREED_NO_TUI=1` | `browse` is the numbered prompt (`--plain` forces it); `search --tui` is the ordinary search with byte-identical output |
| no graphics protocol (`THREED_IMAGE_PROTOCOL`, kitty, iTerm2/WezTerm, sixel terminals) | the picture is drawn as half-block cells (`▀`, 24-bit colour) on a colour terminal |
| no TTY, `NO_COLOR`, `TERM=dumb`, `THREED_IMAGE_PROTOCOL=none` | no picture at all |
| the model (omp) is unavailable | the list stays deterministic; one `!` note says why; `--no-llm` never starts it |

`textual` is an optional extra (`pip install 3d-cli[tui]` / `uv sync --extra tui`), imported only inside the browser's
entry (`lib/library/browse_tui.py`); `3d help` and every other command never load it (`tests/test_imports.py`).
`search --tui` ranks like `--rank` unless `--no-llm`; `browse` resumes the saved verdicts without a model call
and only calls the model when you answer a question or run a follow-up.

The list is in the final ranking order (`fits`, `maybe`, unjudged, `no`; by score inside a class; discovery order
last) and re-sorts live as verdicts arrive. The cursor follows the top of the list until you move it, then it stays
on **its** row. The row number is the row's position in that ranking, the number `3d models act --select` takes.
Row facts come from the search card (`3d.models.search/2`): `size` is the measured bounding box (`--deep` searches)
or `size ?`, `CAD` means a native CAD file is listed (`CAD?` when the file list is unknown).

## Keys

| Key | Does | Equivalent |
|---|---|---|
| `↑` `↓` / `k` `j` | move the cursor | |
| `PgUp` `PgDn`, `Home` `End` / `g` `G` | page, first, last | |
| `space` | select or unselect the row, then move down | `--select 1,3,5-7` |
| `A` | select all visible rows / none | `--select all` |
| `enter`, `p` | **preview**: details, description, tags, file list, analytics; `↑↓` walks the results, `i` draws the picture | `--do preview` |
| `b` | open the page in the web browser | `--do open --yes` |
| `d` | **download** all files + `model.json` (asks `y/n` first, shows the CLI line) | `--do download --yes [--dir D]` |
| `s` | open in the **slicer** (downloads first; asks first) | `--do slicer --yes [--slicer S]` |
| `a` | launch an **agent** with the selected models (asks first) | `--do agent --yes [--agent B] [--prompt T]` |
| `f` | follow-up queries and the planner's questions (below) | `--answer KEY=VALUE`, `--follow N` |
| `r` | **refine**: type a new query; it runs as a child of this search and its hits join the list | `--refine QUERY` |
| `/` | filter the list live (title, site, verdict, licence, tags, rationale); `enter` keeps it, `esc` drops it | `--filter TEXT` |
| `o` | order: verdict then score / as found | |
| `?` | help | |
| `q`, `ctrl+c` | quit | |

The action keys (`p b d s a`) act on the **selection**, or on the row under the cursor when nothing is selected. (The
issue's `A` "apply to all selected" is therefore the default; `A` here selects all visible rows so one `d` takes them
all.) `d`, `s` and `a` start something, so they show `download 2 models?  y / enter = yes, n / esc = no` and the
equivalent `3d models act ... --yes` line first. A failed action is one status line (`download failed: ...`), never a
crash.

### Follow-ups and questions (`f`)

The S6 planner's output (`docs/contracts/search-events.md`): clarifying questions (`single` = pick one, `multi` = a
checklist with `space`, `text` = type an answer) and suggested follow-up queries, plus the queries that already ran.
`enter` on a question answers it inline: the answer is saved, applied as a constraint and the results are judged
again; `enter` on a follow-up runs it as a `followup` session under the same root (`parent_id`) and judges its hits.
New verdicts appear in the list while the model works.

```
 3d models  'case'  10 results  3 fit 2 maybe 5 no                                                        done  LLM omp
      # ver.  scor site   title                                                            size mm cad  licence / price
Follow-ups and questions
enter: answer a question / run a follow-up   esc: back

? need_cad (single): Do you need CAD files?  [yes | no]
? max_size (text): Maximum size in mm?
> follow-up 1 [suggested]: 'plant stake holder'  - a stake variant

 2 selected  cancelled
 ? help  q quit  space select  p preview  b browser  d download  s slicer  a agent  f follow-ups  r refine  / filter
```

### Preview and pictures (`p`, then `i`)

`p` fetches the picture in the background (kitty, iTerm2, sixel, or half blocks) and shows details, description,
files and analytics. `i` suspends the full screen, prints the picture on the terminal, and waits for `Enter`.
`THREED_IMAGE_PROTOCOL=kitty|iterm2|sixel|none` forces a protocol; `--images=PROTO|none` does it per run.

## Configuration

No program path is hard-coded. `~/.config/3d-cli/browser.json` (or the file named by `$THREED_BROWSER_CONFIG`):

```json
{"slicer": "snapmaker-orca",
 "browser": "firefox {url}",
 "agent": {"backend": "omp", "command": ["omp", "@{brief}", "{prompt}"], "prompt": "Read {brief} ..."}}
```

| Setting | Flag | Env | Default |
|---|---|---|---|
| slicer | `--slicer S` | `THREED_SLICER` | first installed of OrcaSlicer, Snapmaker Orca, Creality Print, Bambu Studio (`PATH`, then `~/Applications`, `/Applications`) |
| browser opener | `--browser CMD` | `THREED_BROWSER`, `BROWSER` | `xdg-open` / `open` |
| agent backend | `--agent B` | `THREED_AGENT` | `omp` (`claude`, `codex`, `opencode`) |
| agent mode | `--agent-mode M` | | browser: `attach`; `act`: `auto` (attach on a terminal, else tmux, else detached) |
| download parent | `--dir D` | | `./<site>-<id>-<title>/` per model |

A slicer or opener value is a kind name or a command with `{paths}` / `{url}`. A missing program is exit 127 with
the setting to change; nothing falls back silently to another program.

The agent key writes a **brief** (`brief.md` and `context.json` under `~/.local/state/3d-cli/agent-briefs/<search>/`,
never into your project): the original query, the search id, and for each selected model its title, URL, verdict and
rationale, licence, size, the folder it was downloaded to, the file names and the parsed `model.json` provenance. omp
is started as `omp @brief.md "<prompt>"` in the folder the downloads share (or `--agent-cwd`).

## Resuming, and the library DB

Every search, verdict, question, answer, follow-up and rewrite is written to the library DB as it happens
(`docs/contracts/library-db.md`), so `3d models browse [SEARCH_ID]` rebuilds the same list from the DB without a
network call or a model call (`latest` is the newest search tree, not a rewrite under it). A model downloaded in an
earlier session is recognised by its `model_source` row and reused, never fetched twice.

## Key twin: `3d models act`

`3d models act [SEARCH_ID] --select ... --do ...` (full reference: `docs/commands/models.md`, agent workflow:
`docs/agents/search-workflow.md`). The browser and `act` build the same `ActParams`, call the same
`library.browse_run.perform` and return the same results; `tests/e2e/test_models_browse_parity.py` presses
`p b d s a` in the browser and runs the matching `--do` flags on the same saved search, then compares the
`3d.action/1` documents (only the download folder, source uid and process id may differ).

## Tests

- `tests/test_library_browse_state.py`: the pure state machine (keys to effects, the screen as text) on the **real**
  ranking events of an offline pipeline run (scripted catalogue + scripted model).
- `tests/test_library_browse_tui.py`: the Textual app headless (Pilot): streaming, navigation, multi-select, each hotkey
  calling the matching action with the right selection (actions faked), a question answered inline, a follow-up run,
  refine, resume, the terminal hand-offs, SVG snapshots.
- `tests/test_library_launch.py`: slicer / browser / agent discovery and launch against fake executables; forced
  image-protocol environments; the half-block fallback.
- `tests/e2e/test_models_browse_workflows.py`, `..._parity.py`, `..._pty.py`: `bin/3d models act` end to end, key/flag
  parity, and the browser on a real pty read through a terminal emulator.

## What is not verified live

Covered by tests with fake executables and emulated terminals, **not** by a real GUI session: starting a real slicer
(OrcaSlicer / Snapmaker Orca / Creality Print / Bambu Studio) and its multi-file behaviour; the kitty, iTerm2 and
sixel pictures in a real graphical terminal (the escape sequences are unit-tested, the half-block fallback was
drawn on a pty); an attached real `omp` / `claude` session and tmux inside a real tmux server; macOS and Windows.
