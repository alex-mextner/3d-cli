# Deterministic, GUI-free mesh deformation / reference fitting — tooling research (2026-10-20)

Scope: pick the engine behind a `3d deform` command (grab/smooth/inflate/crease/pinch/relief/remesh/
decimate/symmetrize/fit-to-reference) that is **byte-reproducible, fast on ~400k faces, headless,
Blender-free**, and installable from PyPI wheels on linux x86_64 + macOS arm64. All numbers below were
measured by `docs/research/mesh-fit-bench.py` on the 16-core / 30 GB Linux box (no GPU), unless marked
`[INFERENCE]`. No Blender GUI, no chekhov data: the test mesh is synthetic.

## 1. Summary and recommendation

**Core stack = what the repo already ships + ~100 lines of numpy/scipy, plus two small MIT wheels.**

| Layer | Choice | Why (measured) |
|---|---|---|
| Linear algebra / meshes | `numpy`, `scipy`, `trimesh`, `manifold3d` (already deps) | `scipy.sparse.linalg.splu` is single-threaded and bit-reproducible; no BLAS in the hot path |
| Move / grab (large) | **own ARAP** (cotan, spokes, `splu` prefactored once) — not libigl | 400k faces, 10.9k constraints, 10 local-global iters: **9.3 s** (own) = 9.3 s (libigl); 50k faces **1.1 s**. libigl buys nothing but a 2.5x faster solve phase |
| Move / grab (fast, linear) | **own biharmonic** (`L M⁻¹ L`, prefactored) | 400k: 13.4 s once, then **0.17 s per new handle pose**; libigl `harmonic(k=2)` is 26 s |
| Brush kernels | vectorised numpy + `cKDTree` + sparse adjacency | grab/inflate/pinch/crease/clay on 400k faces: **0.3 s**; smoothing 10 passes 0.03–0.08 s (+0.9 s one-time adjacency) |
| Relief | numpy gradient noise / Voronoi / triplanar / strand noise + **Lipschitz slope clamp** | 5 fields + clamp on 400k verts: **3.2 s**; the clamp makes edge slope ≤ s exactly |
| Remesh (isotropic) | **`gpytoolbox.remesh_botsch`** (MIT) | 400k → 74k faces, 5.3 s, deterministic, best triangle quality (1st-percentile min angle 38.5°) |
| Decimate | **`fast-simplification`** (MIT) | 400k → 72k faces **0.9 s**, deterministic; pyfqmr is equal; use pymeshlab QEC only when angle quality matters |
| Offset / morph / smooth-solid | `scipy.ndimage` + `skimage.measure.marching_cubes` (SDF on a voxel grid) | 400k, 0.2 mm voxel, ±0.3 mm: **3.2 s**, bit-identical, ~VDB-quality. OpenVDB is NOT on PyPI |
| Self-intersection gate | `pymeshlab` (optional) else own KD-tree edge/triangle test | pymeshlab 0.8 s vs own numpy 2.7 s vs Open3D **62 s** on 400k |

**Pip dependency set to add** (Python ≥3.10 as in `pyproject.toml`):
`fast-simplification>=0.2`, `gpytoolbox>=0.3.8` (pulls `scikit-image`, `scs`), `scikit-image>=0.24`
(marching cubes; make it explicit). **Optional extras**, not core: `libigl>=2.6.3` (MPL-2.0, faster
ARAP solve), `cholespy>=2.2` (BSD, ~20–25 % faster Cholesky factor than SuperLU), `pymeshlab>=2025.7`
(GPL-3 + needs `libGL`/`libEGL` at import; self-intersection + fast isotropic remesh fallback),
`potpourri3d` (geodesic falloff, see §6).

Reasoning: every accepted op is either pure numpy/scipy (deterministic by construction) or a compiled
single-threaded kernel whose output we hashed 3x. Anything that needed a heavy native stack
(`bpy`, OpenVDB, pymeshlab, Open3D) was either slower, not deterministic-by-design, GPL, not
installable from PyPI, or needs X/GL system libraries on a headless host.

## 2. Method

* Mesh: geodesic icosphere (frequency n, `20 n²` faces), R = 30 mm, plus seeded smooth radial bumps
  (±1.5 mm), numpy only. **400k** = n 141 → 397,620 faces / 198,812 verts (sha256 of V,F float64/int64
  bytes `efa75fe998846285…`); **50k** = n 50 → 50,000 faces / 25,002 verts (`8a0131a5f0aec2c1…`).
  Identical on Python 3.12 and 3.14.
* Each op runs in a fresh subprocess three times: **A** 8 threads, **B** 8 threads again, **C** 1 thread
  (OMP/OPENBLAS/MKL/NUMEXPR/TBB env + `sched_setaffinity`). `sha_raw` = SHA-256 of float64 V + int64 F
  bytes (strict); `sha_stl` = SHA-256 of trimesh binary STL. Seconds are wall time inside the worker
  (excludes interpreter start / mesh load); RSS is `ru_maxrss` of that process.
* Deformation scenario: handle = verts within 3 mm of the top pole moved +8 mm in z; anchors = bottom cap
  z < −0.9 R (1,381 constraints at 50k, 10,933 at 400k). "Reach" = max distance from the handle at which
  displacement is still ≥ 50 % of the handle's.
* Box: `ssh ultra@65.21.40.51`, jobs through `~/projects/bin/heavy` (one at a time, memory-capped).
  Venvs: `v312` (Python 3.12.15), `v314` (system 3.14.4), `v313` (bpy), conda-forge `vdbenv` (openvdb 13.1).
  Versions: numpy 2.4.6, scipy 1.17.1, trimesh 5.1.1, libigl 2.6.3, manifold3d 3.5.4, pymeshlab
  2025.7.post1, open3d 0.20.0, fast-simplification 0.2.0, pyfqmr 0.5.0, gpytoolbox 0.3.8, cholespy 2.2.0,
  potpourri3d 1.4.0, robust-laplacian 1.1.0, scikit-image 0.26.0, bpy 5.2.2 (py 3.13 only).

## 4. Benchmarks (wall seconds, 8 threads unless noted; `1T` = 1-thread run)

### 4.1 Handle deformation with fixed anchors

| Op | Mesh | Total s | Split | RSS MB | Reach 50 % | Edge-length ratio min/max | Det A=B=1T |
|---|---|---|---|---|---|---|---|
| libigl ARAP, 10 iters | 50k | 0.71 | pre 0.30 + solve 0.21 | 169 | 14.5 mm | 0.975 / 1.33 | yes |
| own ARAP + SuperLU | 50k | 1.08 | pre 0.26 + solve 0.72 | 175 | 14.5 | 0.975 / 1.33 | yes |
| own ARAP + cholespy | 50k | 1.04 | pre 0.27 + solve 0.68 | 155 | 14.5 | same | yes |
| libigl biharmonic (`harmonic k=2`) | 50k | 0.79 | one call | 161 | 39.2 | 1.00 / 1.13 | yes |
| own biharmonic | 50k | 0.62 | pre 0.42 + solve 0.013 | 174 | 39.2 | same | yes |
| libigl ARAP, 10 iters | **400k** | **9.26** | pre 6.04 + solve 2.28 | 853 | 14.7 | 0.975 / 1.41 | yes |
| own ARAP + SuperLU | **400k** | **9.27** | pre 2.54 + solve 5.88 | 978 | 14.6 | 0.975 / 1.41 | yes |
| own ARAP + cholespy | **400k** | **8.37** | pre 2.08 + solve 5.46 | 767 | 14.6 | same | yes |
| libigl biharmonic | **400k** | **26.1** | one call | 1015 | 39.2 | 1.00 / 1.14 | yes |
| own biharmonic | **400k** | **13.4** | pre 12.2 + solve 0.17 | 1295 | 39.2 | same | yes |

* Handle reached the target (mean 8.000 mm). libigl and own ARAP differ < 0.3 % in reach; both are
  "spokes" ARAP with cotan weights ([Sorkine & Alexa 2007](https://igl.ethz.ch/projects/ARAP/arap_web.pdf)).
* Own ARAP solve = 0.59 s/iter (batched 3×3 SVD + `bincount` reductions) vs libigl 0.23 s/iter; with
  anchors fixed the free-block factorisation is reused for every pose, so interactive-style re-posing costs
  only the solve phase. A 4-iteration preview is ≈ 5–6 s on 400k.
* Biharmonic gives smoother, wider falloff (reach 39 mm vs 15 mm) and the lowest edge distortion (max
  stretch 1.14 vs 1.41) but no rotation fix-up, so large rotations shear (ARAP's strength).

### 4.2 Fit to a reference (landmarks = every 400th vertex → nearest target vertex; synthetic target)

| Method | Mesh | Total s | Result | Det |
|---|---|---|---|---|
| biharmonic landmarks, 1 full step | 50k / **400k** | 0.86 / **15.8** (pre 14.6) | mean dist to target 0.845 → 0.478 / **0.799 → 0.321 mm** | yes |
| silhouette fit, orthographic z, 2D nearest contour point, 4 damped rounds | 50k / **400k** | 0.79 / **13.9** (pre 12.0) | contour gap mean/max 0.756/1.88 → **0.027/0.36** mm; 400k 0.727/1.87 → **0.015/0.13** mm | yes |
| TPS RBF (`RBFInterpolator`, 498 landmarks) | 400k | 2.2 | 0.351 mm; edge ratio 0.53–1.56 | **A=B, but 8T ≠ 1T bits** (threaded BLAS in `rbf(V)`) |
| lattice FFD 5×5×5 (own, ridge LSQ) | 400k | 1.4 | worse than start (1.33 mm) — shell landmarks leave the lattice under-determined | **8T ≠ 1T** |

Silhouette fit shortens edges at the limb (ratio min 0.17 at 400k): follow it with a few ARAP/smooth
iterations or limit the step. All fit rows reuse one prefactored matrix across rounds (4 rounds cost
0.1–0.9 s total). Both landmark fits are one-sided (target→nearest vertex), so residual 0.3 mm is partly
target vertex spacing, not fit error.

### 4.3 Brush kernels, smoothing, relief (400k faces)

| Op | Total s | Notes |
|---|---|---|
| grab (smoothstep falloff 8 mm, 2,978 verts) | 0.31 | KD-tree build + ball query 0.21, kernel 0.04 |
| inflate + pinch + crease + clay-flatten | 0.32 | vertex normals 0.05, each kernel < 1 ms on the 3k-vertex selection |
| explicit smoothing, 10 passes | 1.24 | adjacency build 0.87 once; Laplacian λ0.5 0.03, **Taubin** λ0.5/μ−0.53 0.07, HC 0.08 |
| trimesh `filter_laplacian/taubin/humphrey` | 3.29 | first call builds neighbour cache (2.65 s) |
| implicit cotan smoothing (backward Euler, t = 1 mm²) | 3.33 SuperLU / 2.52 cholespy | factor 2.85 / 2.10 s; solve 0.07 / 0.03 s; **volume −0.65 %** |
| symmetrize x→−x (nearest vertex, average) | 0.38 (8T) / 0.97 (1T) | `cKDTree.query(workers=-1)`; per-query results are thread-independent |
| relief: fBm / ridged+warp / Voronoi F1 / triplanar / strand | 0.27 / 0.45 / 0.18 / 0.63 / 0.22 | each field over 198,812 verts |
| Lipschitz slope clamp (5 fields) | 0.54 + graph build 0.87 | converges in 1–4 sweeps |

Smoothing volume change after 10 passes: Laplacian −0.058 %, Taubin +0.003 %, HC 0.000 %. With 0.26 mm
edges 10 passes move vertices only ~0.001–0.008 mm RMS: explicit strength scales with the mesh density
(Blender documents the same: [Smooth brush](https://docs.blender.org/manual/en/latest/sculpt_paint/sculpting/brushes/smooth.html)),
so a feature-size-in-mm control needs ~(size/edge)² passes or one implicit solve.

Slope bound (relief amplitude 0.6 mm, clamp s = 0.7, i.e. 35° edge slope): edge slope after clamp is
**exactly 0.700** for all fields (before: ridged+warp 1.16, triplanar 0.83, strand 1.99). **Measured
face-normal tilt vs the base surface still reached 39–41° max (p99 27–38°)**: an edge-slope bound is not
a face-tilt bound (triangle shape, offset curvature). Budget ~+6° over `atan(s)` or clamp on face
gradients `[INFERENCE]`. Voronoi F1 alone (10° max tilt) needs no clamp.

### 4.7 Other measurements

* Geodesic falloff: potpourri3d heat solver **10.0 s precompute, 1.97 GB RSS**, 0.16 s per source (max
  distance 93.8 mm vs πR = 94.25). Edge-graph Dijkstra with `limit=16 mm` (`scipy.sparse.csgraph`): 0.82 s,
  ~12 % longer than heat distances. For a brush the 3-D sphere falloff (Blender's default *Sphere*
  [falloff shape](https://docs.blender.org/manual/en/latest/sculpt_paint/brush/falloff.html)) is the
  cheap deterministic default; use limited Dijkstra only for "connected only" masks.
* bpy 5.2.2 (py3.13, headless, 400k tris): `foreach_set` import 0.21 s, SMOOTH modifier 0.11 s, voxel
  REMESH 0.5 mm 0.37 s, DECIMATE 0.5 0.63 s, RSS 588 MB. Determinism not tested.
  `bpy.ops.sculpt.brush_stroke` in `blender -b` (5.0.1) and in the pip module (5.2.2):
  `poll() failed, context is incorrect`.

## 5. Determinism findings

* **Bit-identical** (A = B = 1-thread, `sha_raw`) for every op in §4.1–4.5 except TPS-RBF and FFD.
  Python 3.12 vs 3.14 (same numpy/scipy wheels) gave identical `sha_raw` and `sha_stl` for all 11 ops
  compared (ARAP own/libigl, biharmonic, relief, grab, pymeshlab remesh, fast-simplification, pyfqmr,
  manifold, qslim, SDF).
* **Non-deterministic source found: threaded BLAS.** `RBFInterpolator.__call__` and the FFD basis
  product go through dense `matmul`; 8 vs 1 OpenBLAS threads changed the bytes (repeat at the same thread
  count was equal). `3d`'s `cap_threads()` sets BLAS threads to `max_workers()` (not 1), so any deform path
  that touches large dense `@`/`einsum` must pin `OPENBLAS_NUM_THREADS=1` (or use `threadpoolctl`) for the
  reproducibility guarantee. The sparse paths (`splu`, `csr @ dense`, `bincount`, batched `svd`) are unaffected.
* Reduction order matters in my numpy code: vertex normals, ARAP covariances and force sums use
  `np.bincount` (sequential) after a stable sort, never `np.add.at` on shuffled indices or set iteration.
  `np.unique(..., axis=0)` is deterministic. KD-tree ball-query results are sorted before use.
* Thread-count-sensitive *performance* only: manifold (TBB) 0.73 s vs 1.26 s, `cKDTree workers=-1`, OpenVDB 1.7 s vs 5.6 s.
* Not tested: cross-platform (macOS arm64 vs x86_64; Accelerate vs OpenBLAS, FMA) — `[INFERENCE]` that
  float64 results can differ in the last bits; the float32 STL write masks most of it but the SHA only
  matches per platform. Round vertices to e.g. 1e-6 mm before export if cross-platform equality matters.
* Peak RSS of the 400k heavy paths: 0.8–1.4 GB (biharmonic/silhouette factor 1.3–1.4 GB); fits easily in
  the repo's 6 GB `systemd-run` cap.

## 6. What NOT to use, and why

* **`bpy.ops.sculpt.*` / any Blender sculpt operator headless**: needs a 3-D-view/window context; fails
  with `poll() failed, context is incorrect` (reproduced; known in [issue #73321](https://projects.blender.org/blender/blender/issues/73321) and [StackExchange](https://blender.stackexchange.com/questions/168705/bpy-ops-sculpt-brush-stroke-incorrect-context-when-called-using-the-bpy-module-i)).
  What works headless: `bmesh`, `foreach_set` mesh I/O, modifiers via `bpy.ops.object.modifier_apply`
  (Displace, Smooth, Remesh/OpenVDB voxel, Decimate; Laplacian Deform, Surface Deform and Mesh Deform need
  vertex groups / a bind step), Geometry Nodes. Blender's Python threading is unsupported
  ([API gotchas](https://docs.blender.org/api/current/info_gotchas_operators.html)).
* **`bpy` pip wheel as a dependency**: only py3.11 (5.0.1) and py3.13 (5.2.2) wheels exist; none for 3.12/3.14;
  GPL-3; 402 MB linux x86_64 / 245 MB macOS arm64 wheel ([PyPI](https://pypi.org/project/bpy/)); needs X11/GL system libs on this headless box. A `blender -b` subprocess is the
  fallback for Geometry Nodes/Shape-Key work, never the core.
* **OpenVDB from PyPI**: does not exist for modern Python; conda-forge only; Python API lacks level-set filters.
* **`scikit-sparse` / `probreg`**: sdist-only, fail without a C/C++ toolchain. **`pypardiso`**: MKL, threaded.
* **Open3D** for self-intersection (62 s) or as a core dep (needs EGL libs; heavy wheel).
* **pymeshlab as a hard dependency**: GPL-3 inside an MIT project, and `import pymeshlab` requires `libGL.so.1`
  (box needed `LD_LIBRARY_PATH` to a conda `libGL`). Keep optional/subprocess.
* **potpourri3d heat solver** per brush call (10 s / 2 GB precompute); **robust-laplacian** when plain cotan
  (0.14 s) suffices (its intrinsic-Delaunay value is for degenerate meshes).
* **manifold `simplify` / `fast-simplification` / pyfqmr** output as input to ARAP without cleanup (slivers).
* **Lattice FFD** for landmark fits on a shell; **pycpd** at >10k points.
* **Quad remeshers** (Instant Meshes BSD-style, [QuadWild](https://github.com/nicopietroni/quadwild) GPL-3): quad output; STL needs triangles.
* **Differentiable rendering** (nvdiffrast, PyTorch3D): GPU/torch, not byte-reproducible; out of scope.
* **Explicit uniform Laplacian smoothing for volume work**: shrinks (−0.06 % after 10 passes here; far more at coarser meshes).

## 7. Recommended algorithm per op

| Op | Algorithm (all in `docs/research/mesh-fit-bench.py`) |
|---|---|
| **grab / move** (local, big radius, rotation matters) | Handle set = vertices within r of the pick (KD-tree) moved by Δ; anchors = vertices outside 2–3 r; **ARAP** local-global with one prefactored `splu` ([paper](https://igl.ethz.ch/projects/ARAP/arap_web.pdf)); 4–10 iters. Spokes energy, cotan weights, `det(R) > 0` fix. |
| **grab (fast, translation only)** | **Biharmonic displacement** interpolation, prefactored; 0.17 s per pose at 400k ([survey](https://cgl.ethz.ch/Downloads/Publications/Papers/2008/Bot08/Bot08.pdf)). Or the plain sculpt kernel `p += falloff(d/r)·Δ` (0.3 s) for small radii. |
| **smooth** | Fine control: **Taubin** λ|μ ([Taubin 1995](https://graphics.stanford.edu/courses/cs468-01-fall/Papers/taubin-smoothing.pdf)) or **HC** ([Vollmer 1999](https://www.ljll.fr/~frey/papers/meshing/Vollmer%20J.,%20Improved%20Laplacian%20smoothing%20of%20noisy%20surface%20meshes.pdf)): volume change ≤ 0.003 %. Scale-aware/large features: **implicit cotan** `(M + tL)x = Mx₀` ([Desbrun 1999](https://www.multires.caltech.edu/pubs/ImplicitFairing.pdf)), 2.5–3.3 s at 400k, stable for any `t`; volume −0.65 % at `t=1 mm²`, so follow with a volume-preserving scale (`[INFERENCE]`) or use it masked. Always masked by the brush falloff. |
| **inflate** | `p += s·w(d)·n̂` with area-weighted vertex normals (Blender [Inflate](https://docs.blender.org/manual/en/latest/sculpt_paint/sculpting/brushes/inflate.html)); recompute normals after big moves. |
| **pinch** | `p += s·w(d)·(c − p)_tangent` — pulls toward the stroke centre ([Pinch](https://docs.blender.org/manual/en/latest/sculpt_paint/sculpting/brushes/pinch.html)). |
| **crease** | pinch + push along the mean normal (`−depth·w·n̄`); Blender defines crease as push/pull "while pinching" ([Crease](https://docs.blender.org/manual/en/latest/sculpt_paint/sculpting/brushes/crease.html)). Exact Blender C++ formulas were not read; mine is an equivalent `[INFERENCE]`. |
| **clay / flatten** | project onto the plane (mean point, mean normal) with falloff weight. |
| **falloff / masks** | `smoothstep(1−d/r)` = Blender "Smooth" ([falloff presets](https://docs.blender.org/manual/en/latest/sculpt_paint/brush/falloff.html)); masks multiply the weight (landmark volumes = KD-tree balls/boxes; curvature/normal-angle masks from `dot(n, ref)`); symmetry by mirrored-centre second pass. |
| **relief** | Displace along unit vertex normal by a bounded field: gradient noise fBm, ridged + domain warp ([Perlin](https://mrl.cs.nyu.edu/~perlin/paper445.pdf)), Voronoi F1, triplanar blend `|n|⁴`, strand relief = ridged noise stretched along a tangent flow field in the local frame (LIC-style `[INFERENCE]`). **No-overhang:** clamp to the largest `s`-Lipschitz field below `d` (min-plus Bellman–Ford over edges, 1–4 sweeps) so `|Δd| ≤ s·|e|` on every edge, then verify face-normal tilt (§4.3) and `d·κ_max < 1` (offset must not fold: height < smallest radius of curvature); check with the self-intersection gate. Offset-surface tilt is `atan(|(I − dS)⁻¹∇d|)` `[INFERENCE: standard offset geometry, derived, not cited]`. |
| **remesh** | `gpytoolbox.remesh_botsch` (5.3 s / 400k, min-angle p1 38°); pymeshlab isotropic remesh (2.8 s) as GPL optional fallback. Remesh *before* ARAP/relief on coarse regions, not after (fidelity). |
| **decimate** | `fast-simplification` (0.9 s) with `target_reduction`; then one remesh pass if downstream ARAP is planned. |
| **symmetrize** | Mirror plane, `cKDTree` nearest mirrored vertex, average (0.38 s); report max mirror gap and refuse above a tolerance. |
| **offset / smooth-solid / morph** | SDF on a voxel grid → shift level → Gaussian/morphology → marching cubes (3.2 s, 0.2 mm voxel). Union/difference of two solids: `manifold3d` booleans, not SDF. |
| **fit to reference points / mesh** | **Landmark biharmonic** (prefactored), nearest-target correspondences re-estimated each round with a damped step 0.5; add ARAP rounds for rotation fidelity. 400k: 15.8 s total (14.6 s factor once, 0.9 s for 4 rounds). |
| **fit to silhouette** | Orthographic view: limb vertices (`|n·view| < 0.12`) → nearest 2D contour point of the target silhouette (2D `cKDTree`), displace in the image plane only, depth free, same prefactored biharmonic; 4 damped rounds. 400k: contour gap 0.73 → 0.015 mm mean. Multi-view = stack constraints from each view. Rendering of the target silhouette comes from the existing fit-camera tooling, not from a differentiable renderer. |
| **gate after every op** | Edge-length ratio (`min`/`max`) and face-tilt checks (vectorised, ms), self-intersection (pymeshlab if present, else own KD-tree test), `manifold3d` validity (`status() == NoError`). |

## 10. What `3d mesh deform` took from this note (implementation, 2026-10-21)

Command and docs: [docs/commands/mesh.md](../commands/mesh.md); code: `lib/geometry/meshfit/`.

| Decision | Source in this note | Result in the repo |
|---|---|---|
| Own ARAP / biharmonic / cotan on `scipy.sparse` + `splu`, not libigl | §4.1: 9.3 s = 9.3 s at 400k | `deform.py`; `PatchSystem` solves only a local patch (`influence`) so the ARAP step on a 25 mm patch of a 401,868-face mesh is ~1.4 s |
| Brush kernels as vectorised numpy, Taubin smoothing | §4.3, §7 | `brushes.py`; 6-op spec on 401,868 faces ~4 s on the same box |
| Strand relief + overhang control | §4.3 / §7: an edge-slope (Lipschitz) clamp is not a face-tilt bound (39-41 deg for 35 deg) | `relief.py` limits **face normals directly** (a printable face may never exceed the limit, bed faces exempt) and is cross-checked against `printability_mesh.overhang` |
| gpytoolbox `remesh_botsch`, `fast-simplification` | §4.4 | optional engines `botsch` / `quadric`; the default `refine` engine is a conforming midpoint split that keeps every original vertex, which is what lets a keep-out zone stay bit-identical |
| Own KD-tree edge/triangle self-intersection test | §4.6: 2.7 s vs Open3D 62 s | `selfint.py` (pymeshlab first when it imports); Open3D is not used |
| Pin threaded BLAS | §5 | `mesh_deform.py` sets `OPENBLAS/MKL/VECLIB/BLIS_NUM_THREADS=1` before numpy loads; e2e test compares 1 vs 8 threads |
| `bpy.ops.sculpt.*` unusable headless | §6 | not used; no Blender dependency at all |

Not implemented (listed so nobody assumes it): the SDF offset / morph op (§4.5), implicit cotan smoothing, Voronoi / triplanar
relief fields, landmark-biharmonic and per-contour silhouette fits (§4.2). `fit_silhouette` is the smaller, honest variant:
a greedy search over a few named handles. The §4.2 contour fit is the natural next step if a per-vertex fit is wanted.
Dependencies were deliberately not added to `pyproject.toml` / `uv.lock`: every extra is lazily imported and reports its
install line when missing.
